## 1. Feature inventory

### Booking integrity and calendar
| Item | Status | Where | Finding / action | Pri |
|---|---|---|---|---|
| Double-booking prevention | **BROKEN** | `bookings_no_double_book` index, `create_booking()` | Only blocks two bookings with the **same start time**. Reproduced: a 6 h ceramic coating at 08:00 and another at 09:30 on the same day both returned `ok:true`. The booking page also offers every start time inside a long job. Detailer reschedules aren't checked either. **Fix:** an overlap check on insert and update, serialised per detailer (advisory lock), plus busy ranges on the booking page. | P0 |
| Buffer/travel time between jobs | MISSING | none | Mobile detailers have to drive between jobs. **Add** `detailers.buffer_min` and use it in the overlap check. | P1 |
| Booking status integrity | **PARTIAL** | RLS grant `update (… status)` on bookings | A detailer's app can write any status directly, e.g. cancelled → confirmed, or "cancelled" without going through `cancel_booking()` (skips refunds in Stripe mode). The UI never does this, but the server doesn't enforce it. **Fix:** a trigger allowing only valid transitions for direct writes. | P0 |
| Time zone of open days on the booking page | **BROKEN (edge)** | `nextOpenDays()` in `BookingFlow.tsx` | Days are counted in the **visitor's** time zone. A client in another zone (common for UAE/NZ visitors abroad) can see the wrong first day, or a 21st day the server rejects. **Fix:** count days in the detailer's zone. | P1 |
| Slot freed after a detailer cancels | PARTIAL | `api/bookings/[id]/cancel` | The page cache (60 s) isn't revalidated, so a freed slot shows as taken for up to a minute. **Fix:** revalidate the tag. | P1 |
| Rescheduling | MISSING | none | The detailer can only cancel. **Add** reschedule (server-checked) and a prompt to text the client the new time. | P1 |
| Blocked dates / days off | MISSING | none | The only workaround is deleting weekly times. **Add** days off: table with RLS, booking page and `create_booking()` respect them. | P1 |

| Unpaid holds expire | COMPLETE | `create_booking()` | 30 min (Stripe mode only; external mode confirms at once). | – |

## Stage 1 results (P0: booking integrity)
**Changed**
- `supabase/migrations/20261111000000_booking_integrity.sql`
  - `bookings_overlap_check` trigger: a live booking (confirmed, or an unpaid hold under 30 min) can't overlap another
    one, counting the detailer's travel buffer. A per-detailer advisory lock makes two concurrent bookings
    queue up. It covers inserts and any change of time, length or status. Existing rows are not re-checked, so the
    migration can't fail on production data.
  - `detailers.buffer_min` (0-240 min, default 0, so nothing changes until a detailer sets it).
  - `bookings_guard_detailer_update` trigger: the app can only write confirmed → completed / no-show and undo those.
    Cancelling stays in `cancel_booking()`. Times move only through the new `reschedule_booking()` (owner-only,
    future only, overlap-checked, audited). Direct `update (starts_at, duration_min)` revoked from `authenticated`.
  - `create_booking()`: overlaps return `slot_taken`, and all expired unpaid holds are released first.
  - `apply_stripe_event()`: a late payment whose time was taken by an overlapping booking still answers
    `refund_needed` instead of throwing.
  - `get_booking_page()`: adds `busy` (local start + minutes, no client data) and `bufferMin`.
- `apps/web/src/lib/slots.ts` (new): open days counted in the **detailer's** time zone; hides start times whose job
  (selected service length + buffer) would overlap. Used by `BookingFlow.tsx`, which also drops a chosen day/time if a
  longer service is picked afterwards.
- `apps/web/src/app/api/bookings/[id]/cancel/route.ts`: revalidates the booking page so the freed time shows at once.
- `apps/web/src/components/site/HeroLanding.tsx`: "Book now" mock button `#1e8bff` → `#0a6fe0`. **CI on main was
  already failing** since commit 5f148d0 (axe colour-contrast 3.4:1 on `/`); now 4.8:1.

**Tests**
- Reproduced first: two 6 h jobs at 08:00 and 09:30 the same day were both accepted. Now refused.
- `supabase/tests/database/booking_integrity.test.sql` (new, 26 tests): overlap refused/allowed at the boundary, buffer
  on both sides, direct server insert refused, cancelled rows don't block, busy ranges carry no client data, status
  guard (cancel/revive/move refused; done/undo/notes allowed), reschedule overlap/past/ok/audited/cancelled,
  cross-tenant reschedule refused, anon refused.
- One fixture changed in `stripe.test.sql`: it moved a booking 1 minute so it overlapped another 60 min booking, which
  is now (correctly) refused; it now moves it 2 hours.
- Results: database **247/247** pass (221 before + 26). Web unit **53/53** (+9 in `slots.test.ts`, incl. Auckland/LA
  day boundaries). Playwright **9/9** (was 8/9 on main). `next build` + CSP check, `tsc`, `eslint` clean.
